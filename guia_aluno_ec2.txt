1. ACESSAR SUA EC2
================================================================================

Voce recebeu do professor:
  - IP publico da sua EC2 (ex: 54.123.45.67)
  - Chave SSH (.pem)

Conecte-se via terminal:

  ssh -i /caminho/sua-chave.pem admin@<IP-DA-SUA-EC2>

Exemplo:
  ssh -i ~/Downloads/minha-chave.pem admin@54.123.45.67

No Windows, use PowerShell.

================================================================================
2. INSTALAR DOCKER E OS BANCOS
================================================================================

Acesse sua EC2 e execute:

  chmod +x setup_docker.sh
  sudo ./setup_docker.sh

O script instala Docker e sobe 3 containers:

  - MongoDB 7.0  ->  mongosh
  - Redis        ->  redis-cli ping
  - Cassandra 4.1 -> cqlsh

Aguarde de 3 a 5 minutos. Ao final, teste:

  mongosh --eval "db.version()"
  redis-cli ping
  cqlsh -e "DESCRIBE keyspaces;"

5. GERENCIAR OS CONTAINERS
================================================================================

Os bancos rodam dentro de containers Docker.

  # Ver status
  cd /opt/banco2 && docker compose ps

  # Parar tudo
  cd /opt/banco2 && docker compose down

  # Iniciar tudo
  cd /opt/banco2 && docker compose up -d

  # Reiniciar um banco especifico
  docker restart mongodb_banco2
  docker restart redis_banco2
  docker restart cassandra_banco2

  # Ver logs
  docker logs mongodb_banco2 --tail 20
  docker logs cassandra_banco2 --tail 20

7. RESOLVENDO PROBLEMAS COMUNS
==============================================================================

--- PROBLEMA: "Connection refused" ou "container is not running" ---
  Causa: Os containers pararam (ex: reboot da EC2).

  Solucao:
    cd /opt/banco2 && docker compose up -d
    sleep 5
    mongosh --eval "db.version()"

--- PROBLEMA: "Container name already in use" ---
  Causa: Containers antigos parados com o mesmo nome.

  Solucao:
    docker rm -f mongodb_banco2 redis_banco2 cassandra_banco2
    cd /opt/banco2 && docker compose up -d

--- PROBLEMA: "No space left on device" (disco cheio) ---
  Causa: EC2 tem apenas 8GB. Imagens Docker ocupam muito espaco.

  Solucao:
    docker system prune -a -f       # Remove imagens nao usadas
    sudo apt-get clean              # Limpa cache de pacotes
    df -h                           # Confirma espaco livre

--- PROBLEMA: Cassandra nao responde (timeout) ---
  Causa: Cassandra demora 2-3 minutos para iniciar.

  Solucao:
    docker logs cassandra_banco2 --tail 10
    # Se aparecer "Starting listening for CQL clients", esta pronto
    cqlsh -e "DESCRIBE keyspaces;"

--- PROBLEMA: "docker: command not found" ---
  Causa: O script setup_docker.sh nao foi executado ainda.

  Solucao:
    sudo ./setup_docker.sh

--- PROBLEMA: mongosh/redis-cli/cqlsh: command not found ---
  Causa: Os atalhos nao foram criados (script nao terminou ou sem sudo).

  Solucao:
    sudo ./setup_docker.sh   # Executa novamente para recriar os atalhos

--- PROBLEMA: Container morreu sozinho (exited) ---
  Causa: Falta de memoria ou disco.

  Solucao:
    docker logs NOME_DO_CONTAINER --tail 20   # Ver motivo
    docker rm -f NOME_DO_CONTAINER            # Remove
    cd /opt/banco2 && docker compose up -d    # Recria

--- DICA FINAL: Sempre que algo der errado, tente: ---
    docker ps                  # Ve quais containers estao rodando
    docker ps -a               # Ve TODOS (inclusive parados)
    cd /opt/banco2 && docker compose down && docker compose up -d  # Reinicio completo
